# EpicLoot Burst regression

Run `powershell -NoProfile -ExecutionPolicy Bypass -File tests/EpicLootBurst/Run-Tests.ps1` from the repository. Requires Windows .NET Framework 4.8, the .NET SDK, and the installed BepInEx HarmonyX/core dependencies. No release output or game DLL is written by this harness.

The harness compiles the production bridge plus extracted, unchanged production ammo, actual-shot and reload methods. It uses real HarmonyX patches on deterministic game/EpicLoot doubles, testing both relative prefix orders and the additional patches on EpicLoot's own patch methods. It checks 3/5/7/9 ammo, same-prefab stacks, shortage, zero/custom costs, native clusters, one-item refunds, last-successful-shot reload, switching, delayed shots, reselected invalid payloads, resource failure, exceptions, optional absence/disposal, and ordinary/remote/non-Burst exclusion. This is isolated .NET Framework execution, not Unity or Valheim's Mono runtime.

Contract regressions accept identical implementations with different reported plugin versions, an added overload, changed field visibility and a changed enum underlying type/values with an extra member. Runtime-generated incompatible doubles exercise field type/mutability/static requirements and callback argument/return mismatches. Removing each required native Harmony registration also disables the bridge without leaving suppression patches behind. These are synthetic version/contract variations, not tests of unreleased EpicLoot builds. Startup registration checks run once; delayed registration by an external mod is not polled or retried.

`Verify-Contract.ps1` takes `-EpicLootDll`, `-ModDll`, `-GameManaged`, `-BepInExCore`. It verifies the supplied original EpicLoot 0.14.13 SHA-256 `802790E0CBD8A6F951627619A488B84E6A406E8770E2687B2FFF8B63D2ADF9EA`, callback/field metadata, original game access levels, optional assembly boundary, and the merged DLL's payment/shot ordering. This hash/version pin identifies the reviewed test fixture, not a runtime compatibility gate. EpicLoot's assembly version is 0.13.0.0; its BepInPlugin version is 0.14.13. The reviewed original game is Valheim 1.0.17; no game or external mod DLL is publicized for analysis or bundled in these tests. Matching signatures and registrations cannot prove unchanged callback semantics; the bridge continues to call EpicLoot's own effect/refund logic.

Still requires in-game validation: real EpicLoot effects/configuration and projectile damage, cancellation/weapon switch/reload, low ammo over multiple stacks, delayed-source weapons, host/client visuals and inventories. The bridge does not refund attack-start costs or earlier vanilla trigger durability/VFX when the actual shot cannot fire. An exception after payment restores temporary effect state, but does not refund paid ammo because projectile creation may already have partially succeeded.

## Path of Valheiman bridge

The same harness links `Compat/PathOfValheimanCompat.cs`, the production Eitr prefix and saved-reload restoration method. It builds both the earlier extra-burst layout and the new magazine layout without `burstFor`, each in both EpicLoot/SA prefix orders. Deterministic PoV boundary callbacks cover additional burst/cluster counts, per-unit saving, combined EpicLoot refunds and paid-only recovery, empty callback suppression, first-shot reload deferral without EpicLoot, fixed/delayed emission isolation, source/weapon restoration after exceptions, equal/different Eitr costs before active registration, explicit/offline keeper precedence, missing registration rejection and disposal. It does not execute PoV's real node formulas or Unity collision physics.

`Verify-PathOfValheimanContract.ps1 -PathOfValheimanDll <original DLL> -ModDll <merged DLL>` checks the reviewed PoV 5.3.2 fixture (SHA-256 `83BD50F23D9C301FE469B5FBE2C430FD35C928D7A2CCFD99AF5A1040558C9D72`), callback declarations, writable state, optional dependency and original game access restrictions. The fixture pin is a test input identity, not a runtime version restriction. The current original game reference hash is `94998885B103D6E5F5480123EAEE0A093E82AF2DDEEEE37536C15BF555F24F3A` (installed 1.0.20 client); existing publicized compile references are not used as API evidence.

Manual checks still needed with the real PoV build: extra-arrow/bolt and saving/recovery nodes with and without EpicLoot; insufficient ammo and weapon switches; oil/charge/area damage on Cleaving Thrust and Aftershock; fixed Barrage/Sentinel after firing another weapon; Piercing/Scatter continuation and rejected volley hits; summon owner disconnect/reconnect and nearby second players. No multiplayer or live Mono result is implied by these isolated checks. Other PoV nodes, assets, UI and arbitrary configurations were not exhaustively reviewed.

The magazine fixture checks one original trigger consumption at the first successful shot (including EpicLoot refunds), delayed physical unload, duplicate completion, trigger-time measurement, first/last tag lifetime, subsequent refill protection, cancellation after weapon switch, partial/cleared magazine restoration in either callback order, current-weapon ammo-saving context, exception cleanup, resource-query exclusion and partial-new-contract rejection. First-shot conservation remains the trigger's decision even when a later configured repeat pays ammo; this differs from EpicLoot-only's last-shot reload fallback. Doubles isolate the bridge; they are not a reimplementation or validation of PoV's node formulas.

## Original PoV / Mono smoke

`../PoVBridgeSmoke/Run.ps1 -MonoHost <existing x64 Mono host> -PathOfValheimanDll <original 5.3.2 DLL> -OptionalDependencyDirectory <Jotunn directory>` builds a separate test executable against original, unpublicized game assemblies and runs it using the installed game's Mono. It consumes the already merged Debug SA DLL; it does not install or package anything. `bin/Debug/inputs.txt` and `mono.log` record the inputs and result.

The smoke registers the required original PoV Harmony classes, constructs the production binding object, invokes original private Shot/KeepLoaded callbacks and verifies the real magazine writer, remaining count, duplicate rejection and production tag scope. Unity object identity, ownership and clock are fixtures; Attack/Player objects are uninitialized fixtures. Unexecuted Unity RNG/vector internal calls can print standalone-host warnings during JIT. This is 11 managed integration checks on the original runtime, not a full PoV plugin startup or a running Unity client/server. No original DLL is publicized or modified. Remaining live checks include repeated crossbow attacks, node effects, manual/dodge reload, cancellation, equipment switching and multiplayer authority.

Release 1.2.21 on 2026-10-25 passed 104 EpicLoot assertions per run and 32/64 PoV assertions for the earlier/magazine layouts, each in both patch orders. The merged Release DLL passed 84 original PoV/game contracts, the game API checker and all 11 original-PoV Mono checks. Its SHA-256 is `894E295B1BFFC9C3C1A186C796D1F2146F5A92388CB929FB1505C90E99AC9DD7`; both Thunderstore and Nexus ZIPs contain that exact DLL. Plugin/assembly/manifest versions and packaged documents match. These results do not include a live game or multiplayer session.

# EpicLoot Burst regression

Run `powershell -NoProfile -ExecutionPolicy Bypass -File tests/EpicLootBurst/Run-Tests.ps1` from the repository. Requires Windows .NET Framework 4.8, the .NET SDK, and the installed BepInEx HarmonyX/core dependencies. No release output or game DLL is written by this harness.

The harness compiles the production bridge plus extracted, unchanged production ammo, actual-shot and reload methods. It uses real HarmonyX patches on deterministic game/EpicLoot doubles, testing both relative prefix orders and the additional patches on EpicLoot's own patch methods. It checks 3/5/7/9 ammo, same-prefab stacks, shortage, zero/custom costs, native clusters, one-item refunds, last-successful-shot reload, switching, delayed shots, reselected invalid payloads, resource failure, exceptions, optional absence/disposal, and ordinary/remote/non-Burst exclusion. This is isolated .NET Framework execution, not Unity or Valheim's Mono runtime.

Contract regressions accept identical implementations with different reported plugin versions, an added overload, changed field visibility and a changed enum underlying type/values with an extra member. Runtime-generated incompatible doubles exercise field type/mutability/static requirements and callback argument/return mismatches. Removing each required native Harmony registration also disables the bridge without leaving suppression patches behind. These are synthetic version/contract variations, not tests of unreleased EpicLoot builds. Startup registration checks run once; delayed registration by an external mod is not polled or retried.

`Verify-Contract.ps1` takes `-EpicLootDll`, `-ModDll`, `-GameManaged`, `-BepInExCore`. It verifies the supplied original EpicLoot 0.14.13 SHA-256 `802790E0CBD8A6F951627619A488B84E6A406E8770E2687B2FFF8B63D2ADF9EA`, callback/field metadata, original game access levels, optional assembly boundary, and the merged DLL's payment/shot ordering. This hash/version pin identifies the reviewed test fixture, not a runtime compatibility gate. EpicLoot's assembly version is 0.13.0.0; its BepInPlugin version is 0.14.13. The reviewed original game is Valheim 1.0.17; no game or external mod DLL is publicized for analysis or bundled in these tests. Matching signatures and registrations cannot prove unchanged callback semantics; the bridge continues to call EpicLoot's own effect/refund logic.

Still requires in-game validation: real EpicLoot effects/configuration and projectile damage, cancellation/weapon switch/reload, low ammo over multiple stacks, delayed-source weapons, host/client visuals and inventories. The bridge does not refund attack-start costs or earlier vanilla trigger durability/VFX when the actual shot cannot fire. An exception after payment restores temporary effect state, but does not refund paid ammo because projectile creation may already have partially succeeded.
